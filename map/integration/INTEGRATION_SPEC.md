## 1. 坐标契约（务必按这个写死）

```
Blender（源数据，Z-up，米）        :  +X 东，+Y 北，+Z 上，地面 z=0
glTF（Blender glTF 导出，Y-up）    :  (gx, gy, gz) = (bx, bz, -by)
Unity（UniGLTF ScriptedImporter 默认 ReverseZ）:  Unity = (gx, gy, -gz) = (bx, bz, by)
```

### 1.1 Unity 实际坐标 = `(blender.x, blender.z, blender.y)`

- Blender 的**高度 z** → Unity 的 **y**
- Blender 的**北向 y** → Unity 的 **z（符号不变）**
- Blender 的**东向 x** → Unity 的 **x**

**yaw 约定（Unity 左手系）**：`0 = 面朝 +Z（北）`，`90 = 面朝 +X（东）`，顺时针为正；
`forward = (sin yaw, 0, cos yaw)`；从 Blender 平面方向换算 `yaw = atan2(dx, dy)`。
相机 `pitch` 正 = 抬头；Unity 里 `Transform.eulerAngles.x = -pitch`。

### 1.2 旧数据里的 `unity` 字段是另一套约定 —— 别直接喂 Unity

`nav_graph.json` / `collision.json` / `scene_manifest.json` 里的 `unity` 字段都是 `(x, z, -y)`（z 轴取反）。
例子：`scene_manifest` 里食品商店 `center_blender=[102,-62]`，`center_unity=[102,0,62]`；
Unity 实际是 `(102, 0, -62)`。**照抄会把整张地图沿 z 轴翻面。**

AABB 换算：`unity_min=(bx_min, bz_min, by_min)`、`unity_max=(bx_max, bz_max, by_max)`，
各轴 min/max 顺序不需要交换（这是 z 不取反带来的便利；若按旧的 `(x,z,-y)` 换算就必须重排 min/max）。

### 1.3 三个地标的交叉验证（三条独立证据）

**证据 A：直接解 GLB。** 读 `SovietBlueHour_game.glb` 的 JSON chunk，取 `BLD_*` 网格 POSITION accessor
的 min/max（导出时 `export_yup=True`、物体变换已烘焙，除 `BLD_MOTHERLAND` 带 node translation `(0,2.7,0)`）：

| 地标 | GLB(glTF) bbox | 反推 Blender xz | `scene_manifest.rect` | **Unity 实际 bbox** |
|---|---|---|---|---|

参数定义（与 lead 约定一致）：相机方位 bearing = `char_yaw + 180 + yawOffset`
（`yawOffset=0` 在角色正后方，`180` 在正前方 = 面对面，正值为绕向一侧），
`pitch` 正值 = 相机在上往下拍，`lookHeight` = 看向点相对地面的高度。

### 2.4 面对面 vs 越肩：推荐哪种

- **默认用"面对面 3/4"**（数字人展示的第一诉求是看清脸与体态）：`lookHeight 1.10`、`pitch 5~6°`、
  `dist 3.4~4.2`、`yawOffset 200~225°`（即偏离正前方 20~45°，得到 3/4 脸而不是纯正面）。
- **越肩留给"走起来"模式**：`dist 4.2~4.5`、`pitch 10~12°`、`lookHeight 1.25~1.30`，相机在 2.1~2.4m 高，
  这是标准第三人称手感；但画面里是角色后背 + 街景，不适合当数字人主展示。
- 两种机位可以用同一个角色朝向（C1、C3 就是这么配的）；C2 必须靠"转角色"来避免相机下水（见 2.2）。

## 5. 碰撞盒（`collision_boxes`，91 个）

已全部换算成 Unity 实际坐标，保留 `id` / `kind` / `source`（另附 `blender_min/max` 便于复核）。
`min/max` 各轴顺序不需要交换（见 §1.2）。`kind` 分布：`building` 50、`prop` 16、`pole` 9、
`terrace_step` 6、`water` 3、`arch_lintel` 2、`low` 2、`ground` 1、`landmark` 1、`terrace_platform` 1。

Unity 端做障碍时注意：

1. `ground`（GROUND_PLANE）= x[-220,220]、y[-1,0]、z[-170,170]，**顶面 y=0**，角色根节点 y=0 就站在这。
2. `arch_lintel`（2 个拱门过梁）底面 y=2.95 > walk-under 1.75，**可以走下面穿过去**，不要当实心盒。
3. `terrace_step`（6 级台阶，每级 0.45m）+ `terrace_platform`（2.7m 台地）是**可行走表面**，不是障碍。
4. `low`：`TRAM_PLATFORM` 顶面 0.25m（可跨上，站上去 y=0.25）；`LM_FOUNTAIN` 顶面 0.5m（> step 0.35，跨不上去，算障碍）。
5. `water`（3 个）：公园池塘 + 东西两块倒影池。⚠️ 池塘水面实际是**椭圆**，碰撞盒是矩形 AABB，
   四个角各误伤 3~5m 干地（如 x=-25 处椭圆只到 z=99.3，AABB 却从 94 开始）。
6. 大量道具（长椅、路灯、树、垃圾箱）**不在** collision.json 里，视觉与碰撞会有出入，属已知偏差。
